\section{Introduction, Scope \& Product Overview}

\subsection{The Problem: Why Group Planning is Painful}
Planning an outing or trip with friends---whether a weekend cafe hangout or a 4-day vacation---is notoriously frustrating in practice:
\begin{itemize}
\item \textbf{Too many open tabs:} Finding places requires jumping between Google Maps, food review apps, Agoda, Booking.com, and blogs for hours.
\item \textbf{Clashing personal tastes:} Everyone wants something different (e.g., quiet cafe vs. lively pub, budget street food vs. fine dining). Discussions easily stall in deadlock.
\item \textbf{Buried in chat:} Recommendations, links, opening hours, and polls quickly get lost under hundreds of messages in Zalo or Messenger.
\item \textbf{Exhausted organizer:} A single person carries the burden of building the schedule, checking opening hours, and booking transport---and gets blamed if plans fail.
\end{itemize}

\subsection{Target Audience \& Operational Scope: Keeping It Practical}
\label{sec:target_audience}
To keep the engineering scope clear and achievable, \textbf{TripMate AI} intentionally defines its operational boundary:
\begin{itemize}
\item \textbf{Target Users:} Groups of friends, university peers, young families, and colleagues planning leisure, dining, or travel together.
\item \textbf{Scope (No Visa Complexity):} We focus strictly on destinations where users \textbf{already satisfy legal travel prerequisites} (e.g., domestic travel in Vietnam, regional travel within visa-free ASEAN territories, or travelers who already hold valid tourist visas).
\end{itemize}
\textit{Supervisor Rationale:} As advised during evaluation, incorporating consular paperwork, embassy appointments, and international visa rules adds legal friction that distracts from software engineering. By focusing on travelers ready to explore, TripMate AI concentrates 100\% on its core value: \textbf{smart itinerary creation, real-world spot discovery, booking options, and smooth group voting}.

\subsection{The Solution: Two-Stage Consensus Planning Flow}
\textbf{TripMate AI} structures group planning into a clear, two-stage consensus workflow inside a shared room with an AI guide:
\begin{enumerate}
\item \textbf{Capture Desires \& Save to DB:} Friends chat naturally about dates, general budget, and preferred vibes. All user messages and preferences are persisted directly into PostgreSQL.
\item \textbf{Macro Plan Overview:} The AI first generates a high-level roadmap (number of days, daily focus, regional anchors).
\item \textbf{Lock Macro Plan (Macro Consensus):} The group discusses and agrees on the big picture before any specific venues are chosen.
\item \textbf{Micro-Spot Curation:} Once the macro framework is locked, the AI fills each day with real places (morning coffee, lunch, afternoon activity, dinner) clustered close together via live APIs (Google Places, Agoda, Klook).
\item \textbf{Granular Voting \& Swaps:} Members vote thumbs UP/DOWN on individual stops. A downvoted spot can be swapped in one click with a pre-scored alternative.
\item \textbf{Final Plan Lock (Final Consensus):} The group confirms the finished itinerary. It is locked in the database, exportable to calendar (.ics) and PDF, and remains editable live on the go.
\end{enumerate}

\section{Platform Features \& User Experience}

\subsection{Two Flexible Planning Scopes}
\begin{itemize}
\item \textbf{City Hangouts \& Day Outings:} Rapid curation for spontaneous weekend plans (e.g., \textit{``afternoon specialty cafe $\rightarrow$ boardgame lounge $\rightarrow$ hotpot dinner''}). Focuses on venues open right now with minimal transit time.
\item \textbf{Multi-Day Travel Vacations:} Full travel itineraries (e.g., \textit{``4 days in Da Nang \& Hoi An''}). Combines hotel suggestions and transit while **planning every single day with the exact same detail** (breakfast spots, morning sights, scenic cafes, dinner, and nightlife).
\end{itemize}

\subsection{Shared Group Room \& Saved User Data}
\begin{itemize}
\item \textbf{Simple Link Access:} Friends join via link. Roles include \textit{Host} (can lock the plan and manage members), \textit{Member} (can chat, vote on stops, swap places), and \textit{Viewer} (read-only).
\item \textbf{Persistent Dialogue:} Members converse naturally; user messages, individual dietary rules (vegetarian, allergies), and budget limits are **saved directly into PostgreSQL**, allowing the AI to maintain continuous context.
\item \textbf{Event Categories:} \texttt{TRAVEL}, \texttt{DINING}, \texttt{HANGOUT}, \texttt{ENTERTAINMENT}, \texttt{SIGHTSEEING}, and \texttt{CUSTOM}.
\end{itemize}

\subsection{Interactive Timeline \& Live Map}
\begin{itemize}
\item \textbf{Interactive Cards:} The schedule renders as an interactive timeline. Each card displays real photos, verified operating hours, average visit duration, price range, and direct booking links.
\item \textbf{Mapbox Map Integration:} Shows clean geocoded pins, route lines, and travel times. Clicking any stop centers the map immediately.
\item \textbf{Drag-and-Drop Reordering:} Members can manually drag to reorder stops or delete them, with route durations recalculated on the spot.
\end{itemize}

\subsection{Two-Tier Group Consensus: Macro Lock \& Micro Lock}
\label{sec:consensus}
The group always maintains democratic control through two clear stages:
\begin{itemize}
\item \textbf{Stage 1 (Macro Approval):} The group votes on the high-level roadmap (days, cities, themes). Once satisfied, the Host locks the macro framework.
\item \textbf{Stage 2 (Micro Stop Voting):} The AI populates venues. Members vote UP/DOWN on individual stops. A downvoted spot immediately reveals 2 pre-scored alternatives with one-click swap buttons.
\item \textbf{Final Consensus \& Post-Lock Flexibility:} Once all legs are agreed upon, the Host hits \textbf{Confirm Plan}. Status transitions to \texttt{CONFIRMED}. Confirming does not freeze the database; the itinerary remains dynamic and can be adapted anytime during the journey.
\end{itemize}

\section{The AI Agent: Communication, Workflow \& Storage}

\subsection{Model Layer: DeepSeek-V4 Flash \& DeepSeek-V4 Pro}
The agent uses a two-tier model setup in Python via **LangGraph**:
\begin{itemize}
\item \textbf{DeepSeek-V4 Flash:} Fast, cost-effective model used for real-time room chat, parsing user messages, extracting travel dates/vibes, and generating quick conversational replies.
\item \textbf{DeepSeek-V4 Pro:} Deep reasoning model used for multi-day schedule optimization, resolving conflicting member preferences, and clustering venues geographically to prevent zigzag travel.
\end{itemize}

\begin{enumerate}
\item \textbf{Frontend Interaction (WebSockets \& Streaming):} Real-time chat messages, member voting progress, and proposal cards sync instantly over WebSockets. For long answers, Server-Sent Events (SSE) stream tokens progressively to the screen.
\item \textbf{Backend Gateway (FastAPI \& Pydantic v2):} FastAPI receives user requests, enforces JWT authentication and room roles, validates all input/output payloads with Pydantic v2, and dispatches tasks asynchronously to the LangGraph agent.
\item \textbf{Database Storage for User \& Trip Data (PostgreSQL 16):}
  \begin{itemize}
    \item \textbf{User Inputs Saved to DB:} User chat messages, individual preferences (budget, dietary tags), and votes are stored in PostgreSQL tables (\texttt{chat\_messages}, \texttt{event\_members}, \texttt{votes}).
    \item \textbf{Session Checkpoints:} LangGraph's \texttt{AsyncPostgresSaver} preserves dialogue memory and reasoning checkpoints under \texttt{event\_id}.
    \item \textbf{Relational Normalized Plans:} Itineraries are stored as clean relational records:
      $$\text{events} \longrightarrow \text{plans} \longrightarrow \text{plan\_days} \longrightarrow \text{plan\_stops}$$
    \item \textbf{Live Atomic Updates:} Every stop is an independent database row, enabling the AI to update a single venue at any time without rewriting the entire plan.
  \end{itemize}
\item \textbf{External Research APIs \& Curated RAG:}
  \begin{itemize}
    \item \textbf{Stays (Agoda, Booking.com, Airbnb):} Live room rates, amenities, and group homestays.
    \item \textbf{Food \& Sights (Google Places, TripAdvisor):} Verified opening hours, star ratings, and coordinates.
    \item \textbf{Tours \& Experiences (Klook, Traveloka):} Admission tickets and guided activities.
    \item \textbf{Transit \& Weather (Google Flights, 12Go Asia, OpenWeatherMap):} Travel schedules and forecasts.
    \item \textbf{Local Knowledge (pgvector RAG):} Semantic vector search over authentic local hidden gems.
    \item \textbf{Redis Fast Cache:} Caches frequent venue queries (2h--24h TTL) for sub-50ms speed.
  \end{itemize}
\end{enumerate}

\subsection{Step-by-Step Workflow: From General Idea to Detailed Spots}
\label{sec:workflow_steps}
The agent guides the group through a clear, predictable workflow:
\begin{enumerate}[label=\textbf{Step \arabic*:}]
\item \textbf{Conversational Intake:} The AI asks only what is missing: destination area, dates, budget tier, and group vibe. All inputs are saved to PostgreSQL.
\item \textbf{Macro Plan Overview (Big Picture First):} The AI first proposes daily themes (e.g., \textit{Day 1: Arrival \& Beach; Day 2: Culture \& Heritage; Day 3: Scenic Tour}).
\item \textbf{Lock Macro Plan:} The group discusses and approves this big-picture roadmap.
\item \textbf{Detailed Micro Spots (Clustered \& Timed):} The AI fills each day with concrete stops (morning cafe, lunch, afternoon activity, dinner), grouped within a 2--3 km radius to prevent zigzagging, with 1--2 backup alternatives per stop.
\item \textbf{Granular Voting \& Booking Integration:} Members vote on stops and swap places with 1-click alternatives. For complex activities (e.g., boat transfers, guided excursions, private shuttles), the AI provides direct verified booking links via Klook or Traveloka.
\item \textbf{Final Plan Lock \& On-the-Go Flexibility:} The Host confirms the finalized plan. The schedule remains live-editable in the database anytime (e.g., swapping to an indoor cafe if sudden rain occurs during the trip).
\end{enumerate}

\subsection{End-to-End System Execution Flow Across All Components}
\label{sec:system_flow}
The end-to-end operation coordinates all five tiers of the web system (Figure~\ref{fig:system_flow}):
\begin{enumerate}[label=\textbf{Step \arabic*:}]
\item \textbf{User Action on Frontend (React SPA):} A member types a trip idea or votes on a stop in the room. The React client applies optimistic UI rendering and sends the action payload over a secure **WebSocket connection**.
\item \textbf{Gateway Ingestion \& Persistence (FastAPI):} FastAPI's WebSocket manager authenticates the JWT token, validates data schemas using **Pydantic v2**, immediately persists messages and votes into PostgreSQL (\texttt{chat\_messages}, \texttt{votes}), and launches an async AI task.
\item \textbf{AI Context Loading \& Planning (LangGraph):} LangGraph loads session memory from PostgreSQL via \texttt{AsyncPostgresSaver}. **DeepSeek-V4 Flash** generates the Macro Plan Overview (days/themes). After the group locks the macro roadmap, **DeepSeek-V4 Pro** curates micro spots.
\item \textbf{Real-Time Research (Redis \& Live APIs):} The AI queries **Agoda / Booking.com** for stays, **Google Places / TripAdvisor** for dining/hours, **Klook / Traveloka** for tours, and **pgvector** for local hidden gems, clustering stops within 2--3 km to prevent zigzag travel.
\item \textbf{Relational Storage (PostgreSQL 16):} The agent validates the plan and writes normalized records into PostgreSQL:
  $$\text{events} \longrightarrow \text{plans} \longrightarrow \text{plan\_days} \longrightarrow \text{plan\_stops}$$
\item \textbf{Real-Time Broadcast \& Map Rendering (Backend $\rightarrow$ Frontend):} FastAPI pushes the updated itinerary event over WebSockets. The React client's TanStack Query cache refreshes instantly, rendering the timeline cards and drawing route lines on **Mapbox GL JS**.
\item \textbf{On-the-Go Live Modifications:} If unexpected rain occurs on Day 2 of the trip, a user simply chats: \textit{``It's raining, find an indoor cafe nearby''}. The agent updates only the affected \texttt{plan\_stops} row in PostgreSQL, and pushes the live update to everyone's phone screen in real time.
\end{enumerate}

\subsection{Deployment, Security \& Rate Limiting}
\begin{itemize}
\item \textbf{Docker Containers:} Docker Compose packages backend services, Redis, and PostgreSQL for consistent local testing and staging deployment.
\item \textbf{Cloud Deployment:} Frontend hosted on Vercel edge CDN; Backend hosted on Render / Linux VPS.
\item \textbf{Security:} User passwords secured with \texttt{bcrypt}; stateless JWT access tokens paired with Redis-managed refresh tokens; Room-level permissions (Host/Member/Viewer).
\item \textbf{Cost Protection:} Sliding-window rate limiters in Redis prevent excessive AI token usage or runaway external API calls per room.
\end{itemize}
