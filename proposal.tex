\section{Introduction, Scope \& Product Overview}

\subsection{The Problem: Why Group Planning is Painful}
Planning an outing or trip with friends---whether a weekend cafe hangout or a 4-day vacation---is often stressful and time-consuming:
\begin{itemize}
\item \textbf{Too many open tabs:} Finding good places means switching between Google Maps, food reviews, Agoda, Booking.com, and blogs for hours.
\item \textbf{Different personal tastes:} Everyone wants something different (for example: a quiet cafe vs. a busy pub, cheap street food vs. a nice restaurant). Discussions often get stuck because nobody can agree.
\item \textbf{Lost in chat:} Recommendations, links, opening hours, and polls quickly get buried under hundreds of messages in Zalo or Messenger.
\item \textbf{Tired organizer:} Usually, one person ends up doing all the hard work of building the schedule, checking opening hours, and finding routes---and gets blamed if plans go wrong.
\end{itemize}

\subsection{Target Users \& Scope: Keeping It Practical}
\label{sec:target_audience}
To keep the project clear, realistic, and focused on software engineering, \textbf{TripMate AI} sets clear boundaries:
\begin{itemize}
\item \textbf{Target Users:} Groups of friends, university students, young families, and coworkers planning leisure hangouts, dining, or trips together.
\item \textbf{Scope (No Visa Hassles):} We focus strictly on trips where users \textbf{already have the right to travel} (domestic trips in Vietnam, visa-free trips in ASEAN countries, or travelers who already hold valid tourist visas).
\end{itemize}

\subsection{The Solution: Two-Stage Consensus Planning Flow}
\textbf{TripMate AI} makes planning simple through a shared room with a helpful AI travel guide:
\begin{enumerate}
\item \textbf{Chat Ideas \& Save to Database:} Friends chat naturally about dates, approximate budget, and favorite vibes. All messages and preferences are saved directly into PostgreSQL.
\item \textbf{Macro Plan Overview:} The AI first suggests a high-level roadmap (number of days, main areas, and daily themes).
\item \textbf{Lock Macro Plan (Macro Consensus):} The group discusses and agrees on the big picture before picking specific places.
\item \textbf{Micro-Spot Curation:} Once the big picture is agreed, the AI fills each day with real places (morning coffee, lunch, afternoon activity, dinner) located close to each other via live APIs (Google Places, Agoda, Klook).
\item \textbf{Granular Voting \& Swaps:} Members vote thumbs UP/DOWN on individual stops. Anyone can swap a disliked stop with a pre-checked alternative in one click.
\item \textbf{Final Plan Lock (Final Consensus):} The group locks the completed plan. It is saved in the database, exportable to a calendar file (.ics) and PDF, and remains editable live on the go.
\end{enumerate}

\section{Platform Features \& User Experience}

\subsection{Two Flexible Planning Scopes}
\begin{itemize}
\item \textbf{City Hangouts \& Day Outings:} Quick plans for spontaneous weekend activities (for example: \textit{``specialty cafe $\rightarrow$ board game lounge $\rightarrow$ hotpot dinner''}). Focuses on places open right now with short travel distances.
\item \textbf{Multi-Day Vacations:} Full travel itineraries (for example: \textit{``4 days in Da Nang \& Hoi An''}). Combines hotel recommendations and travel routes while \textbf{planning every single day in detail} (breakfast spots, morning sights, scenic cafes, dinner, and evening entertainment).
\end{itemize}

\subsection{Shared Group Room \& Saved User Data}
\begin{itemize}
\item \textbf{Simple Link Access:} Friends join instantly through a shareable link. Roles include \textit{Host} (can lock the plan and manage members), \textit{Member} (can chat, vote on stops, swap places), and \textit{Viewer} (read-only).
\item \textbf{Persistent Group Chat:} Friends talk naturally in chat; user messages, individual food preferences (vegetarian, seafood allergies), and budget limits are \textbf{saved directly into PostgreSQL} so the AI never forgets them.
\item \textbf{Event Categories:} \texttt{TRAVEL}, \texttt{DINING}, \texttt{HANGOUT}, \texttt{ENTERTAINMENT}, \texttt{SIGHTSEEING}, and \texttt{CUSTOM}.
\end{itemize}

\subsection{Interactive Timeline \& Live Map}
\begin{itemize}
\item \textbf{Interactive Cards:} The schedule is displayed as an interactive timeline. Each card shows real photos, verified open hours, estimated visit duration, price range, and direct booking links.
\item \textbf{Mapbox Map Integration:} Displays clear location pins, travel routes, and transit times. Clicking any stop on the schedule centers the map on that place.
\item \textbf{Drag-and-Drop Reordering:} Members can drag and drop stops to reorder or remove them, and travel times update automatically.
\end{itemize}

\subsection{Two-Tier Group Consensus: Macro Lock \& Micro Lock}
\label{sec:consensus}
The group always makes decisions together in two simple stages:
\begin{itemize}
\item \textbf{Stage 1 (Macro Approval):} The group votes on the overall plan (number of days, cities, daily themes). Once everyone is happy, the Host locks the macro roadmap.
\item \textbf{Stage 2 (Micro Stop Voting):} The AI fills in specific venues. Members vote UP/DOWN on individual stops. Any downvoted place immediately offers 2 backup options with a 1-click swap button.
\item \textbf{Final Consensus \& Live Edits:} Once all stops are approved, the Host clicks \textbf{Confirm Plan}. Confirming does not lock the database permanently; the plan stays editable and can be updated anytime during the trip.
\end{itemize}

\section{The AI Agent: Architecture, Workflow \& Storage}

\subsection{Single Unified AI Agent: DeepSeek-V4 with Tool Calling}
Instead of managing multiple disconnected bots, TripMate AI uses a \textbf{single, unified AI Agent powered by DeepSeek-V4}:
\begin{itemize}
\item \textbf{Unified Intelligence:} One cohesive agent handles the entire planning lifecycle. It reads member messages, understands group preferences, creates the high-level roadmap, and calls external tools to find venues.
\item \textbf{LangGraph State Management:} Built with Python's \textbf{LangGraph}, the agent tracks the conversation state step by step, ensuring context is never lost across browser refreshes.
\item \textbf{Tool Calling \& Anti-Zigzag Routing:} The agent uses function calling to query external travel APIs and clusters venues within a 2--3 km radius per half-day block so groups do not waste time traveling back and forth across town.
\end{itemize}

\begin{enumerate}
\item \textbf{Frontend Interaction (WebSockets \& Streaming):} Chat messages, voting counts, and itinerary updates sync live via WebSockets. For detailed suggestions, Server-Sent Events (SSE) stream text smoothly onto the screen.
\item \textbf{Backend Gateway (FastAPI \& Pydantic v2):} FastAPI receives requests, checks user login (JWT), validates data with Pydantic v2, and runs the DeepSeek-V4 agent in the background without freezing the server.
\item \textbf{Database Storage for User \& Trip Data (PostgreSQL 16):}
  \begin{itemize}
    \item \textbf{User Inputs Saved to DB:} Chat messages, budget limits, dietary needs, and votes are safely stored in PostgreSQL tables (\texttt{chat\_messages}, \texttt{event\_members}, \texttt{votes}).
    \item \textbf{Session Checkpoints:} LangGraph's \texttt{AsyncPostgresSaver} saves conversation memory and plan drafts under \texttt{event\_id}.
    \item \textbf{Relational Itineraries:} Saved in normalized tables (\texttt{events} $\rightarrow$ \texttt{plans} $\rightarrow$ \texttt{plan\_days} $\rightarrow$ \texttt{plan\_stops}).
    \item \textbf{Live Atomic Updates:} Each venue is stored as its own row in \texttt{plan\_stops}, so the agent can quickly update a single stop without re-creating the entire plan.
  \end{itemize}
\item \textbf{External Research APIs \& Local Knowledge:}
  \begin{itemize}
    \item \textbf{Hotels \& Homestays (Agoda, Booking.com, Airbnb):} Live pricing, photos, and room availability.
    \item \textbf{Dining \& Cafes (Google Places, TripAdvisor):} Real opening hours, ratings, and exact map coordinates.
    \item \textbf{Tours \& Experiences (Klook, Traveloka):} Activity tickets and guided excursions with clear rates.
    \item \textbf{Transit \& Weather (Google Flights, 12Go Asia, OpenWeatherMap):} Travel times, schedules, and rain forecasts.
    \item \textbf{Local Knowledge (pgvector RAG):} Semantic vector search for authentic local hidden gems.
    \item \textbf{Redis Fast Cache:} Caches frequent search results (2h--24h TTL) to respond in under 50ms and reduce API costs.
  \end{itemize}
\end{enumerate}

\textbf{Dynamic On-the-Go Adaptability:} If travel conditions change unexpectedly (e.g., sudden rain), a member sends a simple message such as \textit{``it is raining, find an indoor cafe nearby''}. The system re-executes this exact asynchronous loop: FastAPI logs the request (Step 2a), the agent queries nearby cafes in parallel (Step 4), modifies \textbf{only the affected single row in \texttt{plan\_stops}} in PostgreSQL (Step 5), and pushes the updated pin to all members in under two seconds (Step 6).

\subsection{Deployment, Security \& Rate Limiting}
\begin{itemize}
\item \textbf{Docker Containers:} Docker Compose packages backend services, Redis, and PostgreSQL for simple local testing and cloud deployment.
\item \textbf{Cloud Hosting:} Frontend hosted on Vercel edge CDN; Backend hosted on Render / Linux VPS.
\item \textbf{Security:} Passwords hashed with \texttt{bcrypt}; stateless JWT access tokens paired with Redis-managed refresh tokens; Room roles (Host/Member/Viewer).
\item \textbf{Cost Protection:} Redis rate limiters prevent excessive AI token usage or runaway external API calls per room.
\end{itemize}

\section{Expected Impact \& Conclusion}

TripMate AI solves the common headaches of group planning:
\begin{itemize}
\item \textbf{Under 15 Minutes:} Replaces days of arguing in group chats with a fast, guided 15-minute agreement session.
\item \textbf{No Stress on One Person:} Group voting and instant alternatives ensure everyone has a voice without one organizer doing all the exhausting work.
\item \textbf{Accurate \& Grounded:} Recommendations come from verified sources (Agoda, Booking, Google Places, Klook), preventing closed shops or unrealistic schedules.
\item \textbf{Live \& Flexible:} Because the plan lives in an active database, groups can modify their schedule anytime, before or during the trip.
\end{itemize}
